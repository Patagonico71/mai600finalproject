# AI Usage Disclosure

**For:** MAI 600 — Final Project (Module 8)
**Project:** Local Hybrid Assistant for Customer Support Ticket Triage

| Item | Response |
|---|---|
| **AI tools used** | Claude as a coding assistant for the notebooks, the evaluation pipeline and the report drafts. ChatGPT for grammar and for translating passages first written in Spanish. Hugging Face for model and embedding research. The system under study runs `llama3.2:3b` locally through Ollama — that model is the object of the experiment, not an authoring tool. |
| **How AI was used** | To help adapting the instructor's notebook to this dataset, to write the retrieval, evaluation and charting code, to diagnose retrieval failures case by case, to design the statistical tests, and to draft the written deliverables. Every number in this repository was produced by running the code. The report generators interpolate directly from the CSVs, so the prose cannot state a figure the run did not produce. |
| **Prompts used (examples)** | "Adapt this notebook to build the knowledge base from real agent answers instead of fictional policy documents." / "Retrieval hit rate is 0.40 — show me the retrieved chunks for the failing cases so I can see why." / "The accuracy cannot go down with RAG, we are doing something wrong." / "Clean the duplicates before running and verify the statistics are correct." |
| **What the AI got wrong** | Six defects reached working code, every one of them producing plausible numbers. (1) The knowledge base first embedded agent answers, so retrieval matched on courtesy boilerplate rather than on the problem. (2) The test split sampled per queue and then truncated the list, silently dropping two queues — including the one the model predicted most often. (3) Format adherence required a *valid* queue name, making it a duplicate of the validity metric and scoring the baseline 0.00 on a format it had followed correctly. (4) The prompt passed the retrieved cases' queue but not their type or priority, so retrieval could not inform two of the three predicted fields. (5) No trivial baseline existed, so metrics were read against the other system version instead of against the floor. (6) The sampling experiment that measures reproducibility across temperatures was first run with three samples per setting, which is too few to tell a stable setting from a lucky one — at three runs a genuinely random temperature repeated itself and looked deterministic. |
| **The most serious error** | None of the above. The evaluation ran for two milestones on a corpus that was never checked for duplicates. The dataset is synthetic and built by paraphrasing templates: the median cosine similarity between a test ticket and its nearest neighbour was 0.906. Scaling the knowledge base over the raw corpus would have raised queue-prediction accuracy to 0.68 and looked like a decisive result, while actually measuring the system finding a reworded copy of the test ticket. Excluding neighbours above 0.85 collapses that number to 0.12. This was caught only because the student pushed back on a result that looked wrong, and it now runs as an assertion in the notebook. |
| **Verification performed** | A supervised classifier trained on all 7,113 labelled tickets was used to establish what the task supports at all, so the system's 0.30 could be read as 88% of a measurable ceiling rather than as a bare number. Four further interventions were tested against that ceiling and reported whether or not they helped; three did not. The notebooks run end to end and every reported figure is interpolated from the CSVs they write. Retrieval was inspected case by case, not only in aggregate. Paired comparisons use McNemar's exact test rather than eyeballing a delta. A majority-class floor is computed for every label. The de-duplication guarantee is an `assert` that fails the run, not a comment. |
| **What this changed about the work** | Four of the substantive findings — the boilerplate retrieval problem, the missing trivial baseline, the reversal of a Module 7 conclusion under a larger sample, and the duplicate contamination — were found by inspecting individual cases after a summary table looked acceptable. The aggregate metrics concealed all four. That is recorded here because it is the most transferable thing learned in this project. |
| **Academic integrity statement** | AI was used as a coding and drafting assistant, not as a substitute for the my own work. The system design, the choice of approach, the decision not to train an adapter, the choice of metrics, the interpretation of the results and the final wording are my own responsibility. |
